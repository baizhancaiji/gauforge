# G16 Web 工作台 · 方向规划

> 状态：方向文档（无实现细节）。现有 `g16web/` 下的代码仅视为一次性原型：
> 它验证了链路可行，但按本文档的标准不构成基础，后续以重构/重写对待。
> 其中有沉淀价值的只有两条：README 的接口清单，以及踩坑记录（Gaussian 输入
> 空行规则、hq CLI JSON 行为、任务环境必须自洽）——转为设计输入，不保留实现。

## 0. 定位

**面向 WSL2 单机的计算化学工作台**，覆盖「输入 → 计算 → 分析」闭环。

- 不是队列面板。队列只是执行器，界面围绕化学对象（分子、计算、结果）组织。
- 非目标：多用户调度、通用作业系统、集群管理——那是 HyperQueue 本体的领域。
- 终局形态之一：作为 DeepSeek DSH 的工具被自然语言调用（见 M5）。

## 1. 设计原则

1. **领域优先**：核心抽象是 InputFile / Molecule / Calculation / Result，先建模再动手。
2. **不造解析轮子**：量子化学输出的解析以 [cclib](https://cclib.github.io/) 为主，
   结构互转用 ASE / OpenBabel；自写解析只允许出现在 cclib 不覆盖的实时进度场景。
3. **契约先行**：先定 API 契约（OpenAPI），前端、后端、未来 DSH 插件吃同一份契约，
   杜绝字段随意漂移。
4. **推送不轮询**：任务状态与日志用 SSE/WebSocket 增量推送。
5. **里程碑可验收**：每个里程碑有明确验收标准，写不出验收标准就不开工。

## 2. 架构方向（分层）

```
前端 (Vite + Vue3/React + 3Dmol.js)
   │ REST + SSE
服务层 (API 契约实现)
领域层 (Calculation 状态机 + SQLite 历史)
   ├── 执行适配器：HyperQueue（CLI/JSON 起步 → 评估官方 Python client）
   │               接口留缝，将来可换 SLURM
   ├── 解析层：cclib（结果）+ 自写增量解析（运行中进度）
   └── 化学层：ASE / OpenBabel（结构读写互转）、cubegen/fchk（轨道）
```

关键取舍：

| 决策点 | 候选 | 当前倾向 | 重新评估时机 |
|---|---|---|---|
| 后端 | FastAPI vs Node | Python（与化学生态同语言） | M0 末 |
| HQ 集成 | CLI JSON vs Python client | CLI JSON 起步 | M1 末 |
| 结果解析 | cclib vs 自写 | cclib，自写仅兜底 | 每个里程碑 |
| 前端 | Vue3 vs React | 不纠结，能快速出 3D 集成即可 | M0 |
| 历史/元数据 | SQLite vs 文件 | SQLite | — |

## 3. 里程碑

### M0 · 契约与骨架（起点，推翻重来）
API 契约定稿（OpenAPI 文档落盘），后端骨架按契约生成，前端空壳连 mock 数据。
**验收**：不看后端代码、只看契约文档，就能说出系统全部能力；前端用 mock 展示
队列/详情/提交三个界面。

### M1 · 队列与监控（核心闭环）
新架构下重做提交与监控：cclib 解析已完成任务，自写增量解析运行中进度，
SSE 推送，SQLite 持久化任务历史（hq 重启后历史仍在）。
**验收**：提交 → 实时看到优化步/SCF → 完成后历史可查、可重开详情。

### M2 · 输入工程（把"编辑输入"做专业）
支持 PDB/MOL/MOL2/GJF 导入与互转（ASE/OpenBabel），页面内 3D 结构预览
（3Dmol.js），可视化 Route 关键词构建器，格式校验规则库沉淀为独立可测模块。
**验收**：从一份 PDB 出发，不手写一行文本，生成合法 opt 输入并提交。

### M3 · 结果分析
能量收敛曲线、频率表与红外谱图（cclib 数据 + 前端绘图）、
fchk → cubegen → 轨道/静电势可视化。
**验收**：打开一份 freq 输出，能看到谱图并画出一条轨道。

### M4 · 工作流
任务链（opt→freq→sp 精修）、接入本机已有的 CREST/xtb 做构象搜索 →
Gaussian 精修的组合流。
**验收**：一个按钮完成"构象搜索 + top N 构象精修"并汇总能量表。

### M5 · DSH 接入
按 M0 契约把「提交计算 / 查进度 / 取消 / 结果摘要」封装为 DSH 工具；
明确安全边界（哪些路径可读、哪些操作可触发）。
**验收**：在 DSH 中用自然语言"帮我优化水分子并看结果"完整走通。

## 4. 质量底线

- 解析层用 `~/g16/tests/` 里的真实输出做金标准回归测试——样本是现成的。
- 状态机与契约必须有自动化测试；契约变更必须走文档 diff。
- 禁止事项：正则堆出来的领域解析、无验收标准的里程碑、绕过契约的前后端私相授受。

## 5. 风险

| 风险 | 应对 |
|---|---|
| cclib 对 G16 新特性覆盖不全 | 自写层只补进度类实时信息；向上游提 patch |
| 长任务 log 持续增长 | 增量读 + 位点续传，不做全量重解析 |
| HQ 升级改变 CLI JSON 结构 | 适配器层隔离 + 金标准测试兜底 |
| WSL2 端口/网络配置差异 | 只绑 127.0.0.1，文档写清 localhost 转发前提 |
| DSH 接口反复变化 | 契约先行，工具层做薄封装 |
